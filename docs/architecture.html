① 整体进程拓扑

客户端→网关→后端服务→MongoDB；4 条 SerLinker TCP 长连接
上行（客户端 → 后端） 下行（后端 → 客户端） 控制 / 模块调用
启动顺序（gateway_server/launch.go: Run）： GetSQLiteConnDB → DoInit → BeginGateServer → sleep 2s → BeginLinkServer(Web/Actor/Modularized/Interactive) → Looping。 后端服务通过 RegisterMonitorLogic 监听 gateway 主动 dial 过来的 TCP 长连接，断线后由 BeginLinkServer 的 goto connTryAgain 模式自动重连。

② 网关内部：DoReadMsg / DoSplit / DoDistribute / SerLinker

关键路径： 客户端字节流 → DoSplit 按模式1（2B 包头长度前缀，MaxPacketBodySize=4096，超长断连）切包到 sliceBuffer， 各包结束下标写入栈上 CutIndexList[1024]；
DoDistribute 从 DistributeDataPool 取 *[]byte， 填入 [SessionID 4B][ProtoNum 2B][Data]，缩切后 把指针通过 SafeSendToLinker 非阻塞投递到 SerLinker.receiveChannel；channel 满则直接 Put 回池，绝不阻塞路由协程。
回包路径：后端 → SerLinker → DoDistribute(sourceSession=0) → GateClientMap[sessionID].writeChan → DoWriteMsg 去除 SessionID 前缀 → 写客户端。

③ 后端服务公共层 server_common · 三协程模型 + 握手

三协程 + ctx 联动： BeginService 主协程负责 Read + DoSplit， context.WithCancel 创建的 ctx 在 return 时 defer cancel()， 自动通知 Transmit / Dispose 退出，杜绝协程泄漏。
握手流程： Dispose 收到 protoNum==0 && gateId<0 的首包，解析 GateIdSyncInfo（JSON 或 Protobuf），通过 CheckConnObjIsExist 防止重复 GateID，再 SetGateId + AddConnObj。
背压： BeginService 写 receiveChannel 用 select/default， 满则归还池并打告警（避免下游慢导致整条网关连接被断开引发雪崩）。

④ 模块系统 ServerModule · 单协程模型 + 同步/异步调用

模块特性

每个模块独占 1 个 goroutine，完全无锁，所有数据通过 channel 进出。

同进程不同模块通过 SynchronousPack2Module / AsynchronousPack2Module 互调。

同步调用

SynchronousPack2Module(modName, "GetUserInfo", args)

从 ModulePackInfoPool 取包，ReturnChan := make(chan, 1)，timer 默认 10s 超时。

异步调用

AsynchronousPack2Module(modName, "UpdateScore", args)

ReturnChan = nil，目标模块处理后不回传。

关闭流程

closeChan 监听 SIGINT/SIGTERM → 调用 ServerDown → wg.Done。

defer recover + PanicStack，保证 panic 不会传染主线。

⑤ 完整数据流 · 上行 + 下行 · 端到端动画

包格式演变：
客户端段： [Head 2B 大端 uint16][ProtoNum 2B][Body]，Body ≤ 4096B；
内部段：[Head 2B][SessionID 4B][ProtoNum 2B][Data]， DoPack 在外层加 2B 包体长度，由 ReadStreamBufferObjectWay = 1 决定。
零逃逸内存池： 全程 *[]byte / *ProtoPackInfo 通过 channel 传递， 接收方 defer Put，禁止 Put(&localVar)。

关键设计哲学： ① 每连接 3 协程（Read / Write / 心跳同步），每模块 1 协程，全程 channel 通信，最大化降低锁竞争； ② 背压非阻塞：写 channel 一律 select/default，满则归还池 + 告警，杜绝雪崩； ③ 无锁路由：协议号→服务名用定长数组，热路径 0 hash； ④ 零逃逸内存池：4 大 sync.Pool 全使用 *T 指针； ⑤ MongoDB 读写分离：atomic.Pointer[mongo.Client] + 30s 健康检查 Ping，故障重建无锁切换。
