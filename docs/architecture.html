① 整体进程拓扑

客户端→网关→后端服务→MongoDB；4 条 SerLinker TCP 长连接
上行（客户端 → 后端） 下行（后端 → 客户端） 控制 / 模块调用
启动顺序（gateway_server/launch.go: Run）： GetSQLiteConnDB → DoInit → BeginGateServer → BeginLinkServer(Web/Actor/Modularized/Interactive) → Looping。 监听及四条连接各自在协程中运行；每条 Linker 首次尝试前等待 3s，单次拨号最多 5s，失败后等待 3s 继续尝试。 断线时关闭本次 socket、通知并等待旧写协程退出，再调用 BeginLinkServer 创建下一次连接流程。
后端启动：InitInfo → RegisterMonitorLogic 绑定配置地址并启动 TCP 监听 → CreateMod（日志初始化 → ModInit → 启动模块协程）→ 注册处理函数 → 等待模块退出。 当前先监听、后注册模块；玩家流量的放行时机由部署准备流程控制。
拓扑边界：每个网关按配置连接四类后端；后端之间的协议可经网关路由转发。 MongoDB/Memcached 客户端在四类后端初始化，Gateway 和机器人跳过数据库客户端初始化。 web_server 当前也是公共 TCP 后端，并未单独实现 HTTP/WS 业务监听；图中的业务职责表示扩展方向。

② 网关内部：DoReadMsg / DoSplit / DoDistribute / SerLinker

关键路径： 客户端字节流 → DoSplit 按配置模式切包；模式1为 2B 长度前缀，客户端包体上限 4094B，内部包体上限 4098B，非法包断连。 模式2使用 | 分隔且不支持包体内该分隔符；模式3固定 556B，含 2B 长度及最多 554B 有效包体，其余补零。 完整包复制到 sliceBuffer， 各包结束下标写入定长 CutIndexList[1024]；
DoDistribute 从 DistributeDataPool 取 *[]byte， 填入 [SessionID 4B][ProtoNum 2B][Data]，缩切后 把指针通过 SafeSendToLinker 非阻塞投递到 SerLinker.receiveChannel；channel 满则直接 Put 回池，绝不阻塞路由协程。
回包路径：后端 → SerLinker → DoDistribute(sourceSession=0) → GateClientMap[sessionID].connection.TrySend → DoWriteMsg 去除 SessionID 前缀 → 写客户端。 客户端发送的 S2S 协议在分发层丢弃；内部控制消息仅在 sessionID == 0 时由网关本地处理，不直接下发客户端。
Session 管理：通过原子计数分配 ID，回绕时跳过 0，并用 LoadOrStore 避免与在线 ID 冲突。 关闭状态与投递使用同一连接锁协调，失败投递由调用方归还缓冲区。

③ 后端服务公共层 server_common · 三协程模型 + 握手

三协程 + ctx 联动： BeginService 主协程负责 Read + DoSplit， context.WithCancel 创建的 ctx 在 return 时 defer cancel()， 通知 Transmit / Dispose 退出；连接关闭信号也能唤醒两者，socket 关闭会唤醒阻塞读取。
握手流程：连接建立后设置 10s 握手读截止时间。Dispose 仅在 protoNum == 0 && sessionId == 0 && gateId < 0 时解析 GateIdSyncInfo（JSON/Protobuf），校验 GateID > 0、LinkerName 非空，清除握手截止时间， 再 SetGateId + AddConnObj。AddConnObj 在锁内拒绝重复 GateID 和已关闭连接；异常握手或包状态会断连。
投递与回收：receiveChannel 和 sendChannel 均通过带关闭锁的非阻塞投递方法入队，失败归还池并计数。 业务包转交模块后，由模块处理函数回收；Dispose 本地处理的握手等分支自行回收。 Transmit 正常发送后归还当前包并清空持有标记；错误或 panic 退出时先 Close 禁止新入队，再回收当前包及队列剩余包。

④ 模块系统 ServerModule · 单协程模型 + 同步/异步调用

模块特性

每个模块由 1 个 goroutine 串行处理协议和接口消息；状态若只在该协程访问，可减少业务锁。共享对象及连接生命周期仍使用同步机制。

receiptChan 容量由 CreateMod 的 chanSize 指定，当前业务示例使用 2048。1h 定时器目前只重置自身，没有发送业务心跳。

同进程不同模块通过 SynchronousPack2Module / AsynchronousPack2Module 互调。

同步调用

SynchronousPack2Module(modName, "GetUserInfo", args)

从 ModulePackInfoPool 取包，返回通道容量为 1；入队与等待结果共用 10s 预算。超时返回 nil；已入队调用不会因此取消，迟到结果可写入缓冲通道。

示例接口名用于说明调用方式；当前 user 示例只注册 C2STest，并未注册 GetUserInfo。

异步调用

AsynchronousPack2Module(modName, "UpdateScore", args)

ReturnChan = nil，目标模块处理后不回传。非阻塞投递，返回 bool 仅表示是否已入队；队列满时回收消息并累计丢弃次数。

关闭流程

closeChan 监听 SIGINT/SIGTERM → 调用 ServerDown → wg.Done。

协议/接口处理函数各有 recover 和回收逻辑；LoadMod 也有 recover，循环自身异常时会退出并执行 wg.Done。当前不是等待所有在途网络消息完成的全局优雅停机流程。

⑤ 完整数据流 · 上行 + 下行 · 端到端动画

包格式演变：
以下为长度前缀模式（模式1）：客户端段 [Head 2B 大端 uint16][ProtoNum 2B][Data]， 完整包 ≤ 4096B，包体（ProtoNum + Data）≤ 4094B，业务 Data ≤ 4092B；
内部段：[Head 2B][SessionID 4B][ProtoNum 2B][Data]， 内部包体 ≤ 4098B，完整包 ≤ 4100B；业务 Data 仍 ≤ 4092B。 内部连接固定使用 ReadStreamBufferObjectWay = 1；客户端使用配置的切包模式。
指针对象池：*[]byte / *ProtoPackInfo 通过 channel 转交所有权。 投递失败由发送方归还，成功后由最终消费者归还；Put 后不可继续访问该对象。
广播：后端发送 S2SGateBroadcast 给网关本地处理，再封装为 S2CBroadcast。 目标列表为空时遍历当前网关在线连接，否则按指定 SessionID 投递；每个客户端使用独立池化缓冲区。

正确归还模式： bufPtr := pool.Get().(*[]byte) → *bufPtr = (*bufPtr)[:actualLen] → channel 传递 → 接收方用毕：*bufPtr = (*bufPtr)[:cap(*bufPtr)] → pool.Put(bufPtr)。 归还 Get 得到的原始指针，避免用局部切片变量的地址替代它；后者可能额外产生逃逸和分配。 当前包与尚未消费的队列包分别清理，不能对已经转交的包再次 Put。 sync.Pool 用于复用而非保证常驻；GC 可清空池中的对象，漏归还也不等同于永久内存泄漏。

关键设计哲学： ① 按职责划分协程：网关客户端及 Linker 主要为读写两协程；后端每连接为 Read / Transmit / Dispose 三协程；每模块一个串行消息循环。
② 有界投递：网络及异步模块消息通常非阻塞入队，队列满则丢弃、回收并统计；同步模块调用在总超时预算内等待。
③ 只读路由表：协议号直接索引数组；连接映射和生命周期仍通过锁、原子量及 sync.Once 协调。
④ 对象复用：五个消息池通过原始指针转移所有权，减少重复分配；具体逃逸和 GC 行为需实测。
⑤ 存储恢复：MongoDB 通过验证后的新客户端替换；Memcache 复用原客户端按需拨号，并合并同进程同 key 的并发加载。

⑧ 防护、存储恢复与运维观测

客户端准入与生命周期

TCP Accept 后、WS Upgrade 前检查白名单和 denylist，再用原子计数预留连接名额；并发上限为 10000。WS 升级失败直接归还预留名额，成功后由连接 Close 归还。

首个完整格式合法包等待 10s，收到残片不会延长期限；之后每轮读取设置 180s 截止时间。超时断连本身不累计非法包次数。

WS 单条消息（含分片）应用数据最多 4096B；HTTP 请求头读取 5s，升级响应写入 5s。每次监听创建独立 ServeMux，只注册 /ws 和 /test。

Close 通过 sync.Once 保证只执行一次。投递与关闭使用连接锁协调，关闭后不再接受新消息；写协程负责归还当前发送包并清理剩余队列。

denylist：内存快照 + SQLite

切包失败调用 RecordInvalidPacket：同 IP 在 10 分钟窗口内累计 3 次，封禁 1 小时。运行期违规次数仅存内存；封禁状态写入 net_sql.db 的 denylist 表，并在重启时加载。

写入尝试和跨网关快照同步间隔均为 1s，过期记录清理间隔为 1 分钟。共享同一数据库文件的网关可同步封禁结果，但违规次数不跨进程合并；不同主机的独立数据库不会自动同步。

最多跟踪 100000 个未封禁 IP；SQLite 使用 WAL，锁等待上限 5s。首次包超时、长间隔连接本身不构成当前封禁条件。

MongoDB 读写客户端与恢复

读、写客户端均通过 Connect 和首次 Ping 后才存入全局原子指针；初始化失败终止启动，写客户端失败时先断开已创建的读客户端。

主程序每 30s 触发健康检查。重建失败保留旧指针；新客户端验证成功后 Swap，再 Disconnect 旧客户端。读写使用各自配置地址，实际读取仍采用驱动默认主节点偏好。

MongoConnectTimeout=10s；MongoPingTimeout=5s；MongoHealthPingTimeout=3s；MongoDisconnectTimeout=5s；业务操作 mongoOpTimeout=5s。连接池每客户端、每 Mongo 服务器最大 100、最小 10。

Memcache 加载合并与故障恢复

初始化 Ping 失败会终止启动。操作超时 500ms，写入 TTL 为 15 分钟。健康检查每 30s Ping；失败时 Close 清理空闲连接，原客户端后续操作按需重新拨号，恢复时输出日志。

MemCacheGetOrLoad 先查缓存，未命中或缓存故障后通过 singleflight 合并同进程同 key 加载，任务内二次查缓存；不同 key 仍可并行。

loader 成功后同步回写缓存，再释放合并任务；回写失败仍返回已加载数据，每位调用者得到独立字节切片。loader 错误返回给等待者，后续请求可重试。

同 key 需有相同加载语义，loader 不可递归加载同 key；此机制不跨进程合并，也不是全局回源限流或不存在数据的负缓存。

观测入口：开启配置 pprof=true 时，主程序在数据库配置的调试端口提供 /debug/pprof/ 和 JSON /metrics；WS 业务端口不继承这些路由。 metrics 包含采样时间、goroutine 数量、gateway_drops 与 server_drops。
计数范围：网关统计 Linker 队列满、客户端投递失败及广播投递失败；后端统计连接接收队列满、协议模块队列满、异步模块队列满及返回网关投递失败。 这些是进程启动以来的累计值，不是覆盖所有原因的端到端丢包统计。
错误分类：CheckIsReadTimeOut 使用 errors.As 找到 net.Error 并检查 Timeout()，普通网络错误不会仅因实现了 net.Error 就被记成超时。
实现边界：目前长度前缀打包函数仍使用 append，尚未增加输出容量与包体长度的集中校验；主要发送入口和切包器另有长度检查。 本页记录已存在的实现，不将待处理建议列为已完成能力。
