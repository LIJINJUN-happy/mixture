# Memcached 缓存测试

本程序直接调用项目的 `MemCacheGetOrLoad`、`MemCacheCmd` 和初始化接口。按项目现有结构提供独立 `main.go`，不修改业务代码或项目的 `net_sql.db`。

在项目根目录执行：

```powershell
# 无需安装 Memcached：用本地最小协议模拟端验证当前缓存封装的行为
go run ./test/memcache

# 连接自己的测试 Memcached，也可填写 Memcached Proxy 的地址
go run ./test/memcache -addr 127.0.0.1:11211 -workers 100 -requests 10000

# 故障改为立即断开，默认则模拟连接建立后不响应
go run ./test/memcache -fault disconnect -workers 50 -requests 500
```

## 场景和指标

1. 缓存命中：预热一个随机 key，并发调用 GetOrLoad。预期内容一致、回源次数为 0。
2. 热点失效：创建并删除本次测试的热点 key，再同时启动一批请求。DEL 模拟失效后的状态，不等待框架固定的 15 分钟 TTL。回源次数大于 1 表示同 key 的并发加载没有合并；实际数量取决于调度和查询耗时。
3. 缓存不可用：断开本程序到缓存的连接，随后模拟超时或断开。先确认直接 GET 失败，再运行 GetOrLoad。当前封装遇到缓存错误会回源，因此预期每个请求都执行 loader，且仍得到正确数据。

每个场景输出请求数量、业务错误/内容不符数量、吞吐、p50/p95/p99 请求延迟、回源次数、回源比例和回源并发峰值。热点场景只发 `workers` 个请求；另两个场景各发 `requests` 个请求。测量采用固定并发、收到结果后再发下一请求，属于闭环负载。

`PASS` 表示三组场景符合当前封装行为，不代表缓存已具备故障保护或已达到生产容量。程序对数据错误、非预期回源情况返回退出码 1。

## 参数与测试边界

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `-addr` | 空 | 为空使用协议模拟端；否则转发到指定真实节点 |
| `-workers` | 100 | 并发工作协程数，最多 10000 |
| `-requests` | 1000 | 命中和故障场景各自请求数，至少 workers，最多 1000000 |
| `-loader-delay` | 50ms | 用 Sleep 模拟数据库读取耗时，不连接 MongoDB |
| `-fault` | timeout | timeout 或 disconnect |
| `-value-size` | 256 | 缓存值大小，单位字节 |

程序使用临时 SQLite 和日志目录初始化框架，路径会输出到终端，日志保留供排查。初始化结束后恢复工作目录。缓存操作超时沿用框架的 500ms，未启动健康检查协程。

故障通过本机临时 TCP 入口注入，不关闭真实 Memcached，不改变其他客户端的连接，也不发送 `flush_all`。测试 key 使用随机前缀，SET 写入沿用框架 15 分钟 TTL。由于原函数的异步回写无法等待，不在退出时删除 key，以免迟到的回写重新创建它们；真实节点中的数据会自行过期。

默认模拟端仅实现本测试需要的 version/get/gets/set/delete，gets 返回固定 CAS 占位值，不支持 CAS 更新；不实现真实过期、淘汰、内存限制或集群行为，不能用于估算 Memcached 容量。真实节点模式也经过本地转发入口，测得的是整个测试链路；要结合服务端 stats、CPU、内存和网络判断瓶颈。

loader 是独立可并发的模拟查询，不代表 MongoDB 的真实性能；回源次数代表潜在数据库调用量。测试直接并发调用缓存封装，不模拟模块串行调度、业务排队或真实玩家请求。请求延迟统计不包含异步 SET 完成时间；退出时尚未完成的回写会随测试进程结束，不将其计为业务错误。

建议先用默认规模检查行为，再逐步增加 workers 和 requests；比较单节点与 Proxy 时保持参数和缓存值大小一致。同时检查缓存命中率、超时、连接数、数据库回源预算以及业务模块延迟。
